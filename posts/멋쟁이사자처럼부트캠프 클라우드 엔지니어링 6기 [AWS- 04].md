<h1 id="til-aws-기반의-고가용성-웹-아키텍처-실습">[TIL] AWS 기반의 고가용성 웹 아키텍처 실습</h1>
<h2 id="1-vpc-생성-및-고가용성-네트워크-인프라-구축">1. VPC 생성 및 고가용성 네트워크 인프라 구축</h2>
<p>2개의 가용 영역(ap-northeast-2a, ap-northeast-2b)을 활용하는 멀티 AZ 기반의 격리된 사설 네트워크 인프라를 구축하는 과정.</p>
<hr />
<h3 id="11-vpc-virtual-private-cloud-생성">1.1 VPC (Virtual Private Cloud) 생성</h3>
<p>AWS 클라우드 환경 내에서 격리된 독립적인 가상 네트워크 공간을 정의한다.</p>
<ol>
<li><strong>VPC 관리 콘솔</strong> 이동 후 <strong>[VPC 생성]</strong> 버튼을 클릭한다.</li>
<li><strong>VPC 설정</strong>을 다음과 같이 구성한다:<ul>
<li><strong>생성할 리소스</strong>: <code>VPC만 (VPC only)</code> 선택</li>
<li><strong>이름 태그 (Name)</strong>: <code>bootcamp-vpc</code></li>
<li><strong>IPv4 CIDR 블록</strong>: <code>IPv4 CIDR 수동 입력</code> 선택</li>
<li><strong>IPv4 CIDR</strong>: <code>10.17.0.0/16</code> </li>
<li><strong>텐넌시</strong>: <code>기본값 (Default)</code></li>
</ul>
</li>
<li><strong>[VPC 생성]</strong>을 완료한다.</li>
</ol>
<hr />
<h3 id="12-멀티-가용-영역multi-az-기반-서브넷-생성">1.2 멀티 가용 영역(Multi-AZ) 기반 서브넷 생성</h3>

<ol>
<li><strong>VPC 콘솔</strong> -&gt; <strong>[서브넷]</strong> -&gt; <strong>[서브넷 생성]</strong>을 클릭한다.</li>
<li><strong>VPC ID</strong>에서 방금 생성한 <code>bootcamp-vpc</code>를 선택한다.</li>
<li>아래 표의 설계에 따라 <strong>4개의 서브넷</strong>을 순차적으로 추가 및 생성한다:</li>

<h3 id="13-인터넷-게이트웨이igw-생성-및-vpc-연결">1.3 인터넷 게이트웨이(IGW) 생성 및 VPC 연결</h3>
<p>퍼블릭 서브넷이 외부 인터넷망과 양방향 통신을 할 수 있도록 게이트웨이를 연결한다.</p>
<ol>
<li><strong>VPC 콘솔</strong> -&gt; <strong>[인터넷 게이트웨이]</strong> -&gt; <strong>[인터넷 게이트웨이 생성]</strong>을 클릭한다.</li>
<li><strong>이름 태그</strong>: <code>bootcamp-igw</code> 입력 후 생성을 완료한다.</li>
<li>생성된 <code>bootcamp-igw</code>를 선택한 후, 우측 상단의 <strong>[작업] -&gt; [VPC에 연결 (Attach to VPC)]</strong>을 선택한다.</li>
<li>연결할 VPC로 <code>bootcamp-vpc</code>를 지정하고 <strong>[인터넷 게이트웨이 연결]</strong>을 완료한다.</li>
</ol>
<hr />
<h3 id="14-퍼블릭-라우팅-테이블route-table-생성-및-서브넷-라우팅-설정">1.4 퍼블릭 라우팅 테이블(Route Table) 생성 및 서브넷 라우팅 설정</h3>
<p>퍼블릭 서브넷 전용 라우팅 테이블을 신규 생성하여 IGW를 통신 라우팅 경로를 정의한다.</p>
<ol>
<li><strong>VPC 콘솔</strong> -&gt; <strong>[라우팅 테이블]</strong> -&gt; <strong>[라우팅 테이블 생성]</strong>을 클릭한다.</li>
<li><strong>라우팅 테이블 설정</strong>:<ul>
<li><strong>이름</strong>: <code>bootcamp-public-rt</code></li>
<li><strong>VPC</strong>: <code>bootcamp-vpc</code> 선택 후 생성을 완료한다.</li>
</ul>
</li>
<li><strong>인터넷 외부 경로(0.0.0.0/0) 추가</strong>:<ul>
<li>생성된 <code>bootcamp-public-rt</code>를 선택하고 하단의 <strong>[라우팅] -&gt; [라우팅 편집]</strong>을 클릭한다.</li>
<li><strong>[라우팅 추가]</strong>를 클릭하여 다음과 같이 입력한다:<ul>
<li><strong>대상 (Destination)</strong>: <code>0.0.0.0/0</code> (모든 외부 인터넷 트래픽)</li>
<li><strong>타겟 (Target)</strong>: <code>인터넷 게이트웨이</code> 선택 -&gt; 생성해 둔 <code>bootcamp-igw</code> 지정</li>
</ul>
</li>
<li><strong>[변경 사항 저장]</strong>을 누른다.</li>
</ul>
</li>
<li><strong>퍼블릭 서브넷 명시적 연결</strong>:<ul>
<li><code>bootcamp-public-rt</code> 라우팅 테이블의 하단 탭에서 <strong>[서브넷 연결] -&gt; [서브넷 연결 편집]</strong>을 클릭한다.</li>
<li>가용 영역 A와 B의 퍼블릭 서브넷인 <code>bootcamp-public-subnet-a</code>와 <code>bootcamp-public-subnet-b</code> 2개를 체크한 뒤 <strong>[연결 저장]</strong>을 완료한다.</li>
</ul>
</li>
</ol>
<hr />
<h2 id="2-nat-게이트웨이-생성을-통한-프라이빗-서브넷-인터넷-통신-구축">2. NAT 게이트웨이 생성을 통한 프라이빗 서브넷 인터넷 통신 구축</h2>
<p>프라이빗 서브넷에 배치될 내부 애플리케이션(Spring 및 RDS) 서버들이 외부에 직접 노출되지 않으면서, 패치 및 라이브러리 다운로드 등을 위해 외부 인터넷과 통신할 수 있도록 단방향 통신 통로를 구축하는 과정이다. </p>
<hr />
<h3 id="21-멀티-가용-영역-기반-nat-게이트웨이-생성">2.1 멀티 가용 영역 기반 NAT 게이트웨이 생성</h3>
<p>인터넷과 직접 통신이 가능한 <strong>퍼블릭 서브넷</strong>에 각각 NAT 게이트웨이를 배치한다.</p>
<ol>
<li><strong>VPC 콘솔</strong> -&gt; <strong>[NAT 게이트웨이]</strong> -&gt; <strong>[NAT 게이트웨이 생성]</strong>을 클릭한다.</li>
<li><strong>첫 번째 NAT 게이트웨이 (AZ-A용)</strong> 설정을 다음과 같이 구성 후 생성한다:<ul>
<li><strong>이름 (Name)</strong>: <code>bootcamp-nat-gateway-a</code></li>
<li><strong>가용성 모드</strong>: <code>영역별</code></li>
<li><strong>서브넷</strong>: <code>bootcamp-public-subnet-a</code> (퍼블릭 영역 선택 필수)</li>
<li><strong>연결 유형</strong>: <code>퍼블릭 (Public)</code></li>
<li><strong>탄력적 IP 할당 ID</strong>: <code>탄력적 IP 할당</code> 클릭</li>
</ul>
</li>
<li>다시 <strong>[NAT 게이트웨이 생성]</strong>을 클릭하여 <strong>두 번째 NAT 게이트웨이 (AZ-B용)</strong> 설정을 구성 후 생성한다:<ul>
<li><strong>이름 (Name)</strong>: <code>bootcamp-nat-gateway-b</code></li>
<li><strong>가용성 모드</strong>: <code>영역별</code></li>
<li><strong>서브넷</strong>: <code>bootcamp-public-subnet-b</code> (퍼블릭 영역 선택 필수)</li>
<li><strong>연결 유형</strong>: <code>퍼블릭 (Public)</code></li>
<li><strong>탄력적 IP 할당 ID</strong>: <code>탄력적 IP 할당</code> 클릭</li>
</ul>
</li>
</ol>
<hr />
<h3 id="22-프라이빗-서브넷-전용-라우팅-테이블-생성-및-nat-매핑">2.2 프라이빗 서브넷 전용 라우팅 테이블 생성 및 NAT 매핑</h3>
<p>각 가용 영역의 프라이빗 서브넷 트래픽이 동일한 가용 영역의 NAT 게이트웨이로 흐르도록 독립된 라우팅 테이블을 각각 생성한다.</p>
<ol>
<li><strong>VPC 콘솔</strong> -&gt; <strong>[라우팅 테이블]</strong> -&gt; <strong>[라우팅 테이블 생성]</strong>을 클릭한다.</li>
<li><strong>AZ-A 프라이빗 라우팅 테이블</strong> 생성:<ul>
<li><strong>이름</strong>: <code>bootcamp-private-rt-a</code></li>
<li><strong>VPC</strong>: <code>bootcamp-vpc</code> 선택 후 생성을 완료한다.</li>
</ul>
</li>
<li><strong>AZ-B 프라이빗 라우팅 테이블</strong> 생성:<ul>
<li><strong>이름</strong>: <code>bootcamp-private-rt-b</code></li>
<li><strong>VPC</strong>: <code>bootcamp-vpc</code> 선택 후 생성을 완료한다.</li>
</ul>
</li>
</ol>
<h4 id="221-라우팅-테이블별-외부-인터넷-경로00000-및-서브넷-매핑">2.2.1 라우팅 테이블별 외부 인터넷 경로(0.0.0.0/0) 및 서브넷 매핑</h4>

<ul>
<li><strong>라우팅 편집</strong>: 해당 라우팅 테이블 선택 -&gt; <strong>[라우팅 편집]</strong> -&gt; <strong>[라우팅 추가]</strong><ul>
<li><strong>대상</strong>: <code>0.0.0.0/0</code></li>
<li><strong>타겟</strong>: <code>NAT 게이트웨이</code> 선택 -&gt; <code>bootcamp-nat-gateway-a</code> 지정 후 저장</li>
</ul>
</li>
<li><strong>서브넷 연결</strong>: 하단 <strong>[서브넷 연결] -&gt; [서브넷 연결 편집]</strong> 클릭<ul>
<li><code>bootcamp-private-subnet-a</code> 선택 후 <strong>[연결 저장]</strong></li>
</ul>
</li>
</ul>
<h5 id="2-bootcamp-private-rt-b-설정">2) bootcamp-private-rt-b 설정</h5>
<ul>

<ul>
<li><strong>대상</strong>: <code>0.0.0.0/0</code></li>
<li><strong>타겟</strong>: <code>NAT 게이트웨이</code> 선택 -&gt; <code>bootcamp-nat-gateway-b</code> 지정 후 저장</li>
</ul>
</li>
<li><p><strong>서브넷 연결</strong>: 하단 <strong>[서브넷 연결] -&gt; [서브넷 연결 편집]</strong> 클릭</p>
<ul>
<li><code>bootcamp-private-subnet-b</code> 선택 후 <strong>[연결 저장]</strong></li>
</ul>
<hr />
</li>
</ul>
<h2 id="3-bastion-호스트를-통한-고가용성-시스템-접속-기반-구축">3. Bastion 호스트를 통한 고가용성 시스템 접속 기반 구축</h2>
<p>외부 인터넷망에서 직접 접근이 불가능한 프라이빗 서브넷(<code>private-subnet-a</code>, <code>private-subnet-b</code>) 내부의 인스턴스들에 접근하가기 위해, 퍼블릭 서브넷에 인스턴스인 Bastion 호스트를 구축하는 과정이다. </p>
<hr />
<h3 id="31-bastion-호스트-보안-그룹sg-생성-및-인바운드-규칙-설정">3.1 Bastion 호스트 보안 그룹(SG) 생성 및 인바운드 규칙 설정</h3>
<p>Bastion 호스트 자체를 보호하기 위해 관리자의 특정 IP(또는 실습을 위한 전체 오픈)로부터의 SSH 접속만 허용하는 보안 그룹을 생성한다.</p>
<ol>
<li><strong>VPC 관리 콘솔</strong> -&gt; <strong>[보안 그룹]</strong> -&gt; <strong>[보안 그룹 생성]</strong>을 클릭한다.</li>
<li><strong>기본 상세 정보</strong> 설정을 다음과 같이 구성한다:<ul>
<li><strong>보안 그룹 이름</strong>: <code>bootcamp-bastion-sg</code></li>
<li><strong>설명</strong>: <code>Security Group for Bastion Host</code></li>
<li><strong>VPC</strong>: <code>bootcamp-vpc</code> 선택</li>
</ul>
</li>
<li><strong>인바운드 규칙(Inbound Rules)</strong>을 추가한다:<ul>
<li><strong>유형</strong>: <code>SSH</code> (22번 포트)</li>
<li><strong>소스</strong>: <code>내 IP</code> 또는 실습 편의상 <code>Anywhere-IPv4 (0.0.0.0/0)</code> 선택</li>
<li><strong>유형</strong>: <code>HTTP</code> (80번 포트)</li>
<li><strong>소스</strong>: <code>내 IP</code> 또는 실습 편의상 <code>Anywhere-IPv4 (0.0.0.0/0)</code> 선택</li>
</ul>
</li>
<li>하단의 <strong>[보안 그룹 생성]</strong>을 클릭한다.</li>
</ol>
<hr />
<h3 id="32-bastion-호스트-ec2-인스턴스-생성-및-배치">3.2 Bastion 호스트 EC2 인스턴스 생성 및 배치</h3>
<p>외부 통신 및 주소 자동 할당이 활성화된 퍼블릭 서브넷 A에 Bastion 인스턴스를 생성한다.</p>
<ol>
<li><strong>EC2 관리 콘솔</strong> -&gt; <strong>[인스턴스]</strong> -&gt; <strong>[인스턴스 시작]</strong>을 클릭한다.</li>
<li><strong>이름 및 태그</strong>: <code>bootcamp-bastion</code> 입력</li>
<li><strong>애플리케이션 및 OS 이미지</strong>: <code>Ubuntu Server 24.04</code>선택</li>
<li><strong>인스턴스 유형</strong>: <code>t3.small</code> (프리티어) 선택</li>
<li><strong>키 페어</strong>: 기존 소지한 키 페어를 선택하거나 신규 생성(<code>bootcamp-key</code>) 후 <code>.pem</code> 파일을 안전하게 다운로드한다.</li>
<li><strong>네트워크 설정</strong> -&gt; 우측 상단의 <strong>[편집]</strong> 클릭 후 다음과 같이 변경한다:<ul>
<li><strong>VPC</strong>: <code>bootcamp-vpc</code></li>
<li><strong>서브넷</strong>: <code>bootcamp-public-subnet-a</code> (가용 영역 A의 퍼블릭 서브넷 선택)</li>
<li><strong>퍼블릭 IP 자동 할당</strong>: <code>활성화</code> (서브넷 기본값에 의해 활성화되어 있음)</li>
<li><strong>방화벽(보안 그룹)</strong>: <code>기존 보안 그룹 선택</code> -&gt; <code>bootcamp-bastion-sg</code> 체크</li>
</ul>
</li>
<li><strong>[인스턴스 시작]</strong>을 클릭하여 생성을 완료한다.</li>
</ol>
<hr />
<h3 id="33-고가용성-프라이빗-서버용-내부-보안-그룹sg-설계">3.3 고가용성 프라이빗 서버용 내부 보안 그룹(SG) 설계</h3>
<p>향후 가용 영역 A와 B의 프라이빗 서브넷에 배치될 Spring 애플리케이션 서버들이 Bastion 호스트로부터의 접속만 허용하도록 전용 내부 보안 그룹을 정의한다.</p>
<ol>
<li><strong>VPC 콘솔</strong> -&gt; <strong>[보안 그룹]</strong> -&gt; <strong>[보안 그룹 생성]</strong>을 클릭한다.</li>
<li><strong>기본 상세 정보</strong> 설정:<ul>
<li><strong>보안 그룹 이름</strong>: <code>bootcamp-private-was-sg</code></li>
<li><strong>설명</strong>: <code>Security Group for Private Spring WAS Servers</code></li>
<li><strong>VPC</strong>: <code>bootcamp-vpc</code> 선택</li>
</ul>
</li>
<li><strong>인바운드 규칙(Inbound Rules)</strong> 추가 (체이닝 설정):<ul>
<li><strong>유형</strong>: <code>SSH</code> (22번 포트)</li>
<li><strong>소스</strong>: <code>사용자 지정</code> 선택 후, 방금 전 생성한 <code>bootcamp-bastion-sg</code>의 보안 </li>
<li><strong>유형</strong>: <code>HTTP</code> (80번 포트)</li>
<li><strong>소스</strong>: <code>사용자 지정</code> 선택 후, 방금 전 생성한 <code>bootcamp-bastion-sg</code>의 보안 </li>
<li><em>이 설정을 통해 오직 Bastion 호스트를 거친 트래픽만 프라이빗 서버로 진입할 수 있게 차단된다.</em></li>
</ul>
</li>
<li>하단의 <strong>[보안 그룹 생성]</strong>을 클릭한다.</li>
</ol>
<hr />
<h3 id="34-프라이빗-서버-ec2-인스턴스-생성-및-배치">3.4 프라이빗 서버 EC2 인스턴스 생성 및 배치</h3>
<p>외부 통신 및 주소 자동 할당이 활성화된 퍼블릭 서브넷 A에 Bastion 인스턴스를 생성한다.</p>
<ol>
<li><strong>EC2 관리 콘솔</strong> 이동 후 <strong>[인스턴스]</strong> -&gt; <strong>[인스턴스 시작]</strong>을 클릭한다.</li>
<li><strong>첫 번째 WAS 인스턴스 (Instance A) 설정</strong>:<ul>
<li><strong>이름 및 태그</strong>: <code>bootcamp-was-a</code></li>
<li><strong>애플리케이션 및 OS 이미지</strong>: <code>Ubuntu Server 24.04</code> 선택</li>
<li><strong>인스턴스 유형</strong>: <code>t3.small</code> (프리티어) 선택</li>
<li><strong>키 페어</strong>: Bastion 호스트와 동일한 키 페어(<code>bootcamp-key</code>) 선택</li>
<li><strong>네트워크 설정 (편집 클릭)</strong>:<ul>
<li><strong>VPC</strong>: <code>bootcamp-vpc</code></li>
<li><strong>서브넷</strong>: <code>bootcamp-private-subnet-a</code> (프라이빗 서브넷 A 지정)</li>
<li><strong>퍼블릭 IP 자동 할당</strong>: <code>비활성화</code> (외부 노출 방지)</li>
<li><strong>방화벽(보안 그룹)</strong>: <code>기존 보안 그룹 선택</code> -&gt; <code>bootcamp-private-was-sg</code> 선택</li>
</ul>
</li>
</ul>
</li>
<li><strong>두 번째 WAS 인스턴스 (Instance B) 설정</strong>:<ul>
<li>위의 과정을 동일하게 반복하되, 가용 영역 B의 인프라를 타겟으로 지정한다.</li>
<li><strong>이름 및 태그</strong>: <code>bootcamp-was-b</code></li>
<li><strong>서브넷</strong>: <code>bootcamp-private-subnet-b</code> (프라이빗 서브넷 B 지정)</li>
<li><strong>방화벽(보안 그룹)</strong>: 동일하게 <code>bootcamp-private-was-sg</code> 선택</li>
</ul>
</li>
</ol>
<hr />
<h3 id="35-bastion-호스트를-통한-프라이빗-영역-접속-검증">3.5 Bastion 호스트를 통한 프라이빗 영역 접속 검증</h3>
<p>고가용성 인프라에서 관리자가 프라이빗 서브넷 A 혹은 B에 터널링하여 접속하는 논리적 절차는 다음과 같다.</p>
<ol>
<li><p><strong>로컬 PC에서 Bastion 호스트로 접속</strong>:</p>
<pre><code class="language-bash">ssh -i &quot;bootcamp-key.pem&quot; ec2-user@&lt;BASTION_PUBLIC_IP&gt;</code></pre>
<ul>
<li>위 예시는 로컬에서 ssh로 접속하지만, <code>MobaXterm</code>, <code>AWS 인스턴스 연결</code> 등 Bastion 호스트로 접속하는 어떤 방법이던 상관 없다.</li>
</ul>
</li>
<li><p><strong>Bastion 호스트 내부에서 프라이빗 인스턴스로 2차 SSH 접속</strong>:</p>
<ul>
<li>로컬의 키 페어(<code>bootcamp-key.pem</code>)를 Bastion 호스트 내부로 옮긴 뒤 프라이빗 서브넷 내부 서버의 사설 IP로 접속을 수행한다.<pre><code class="language-bash">ssh -i &quot;bootcamp-key.pem&quot; ec2-user@&lt;PRIVATE_SUBNET_A_OR_B_IP&gt;</code></pre>
</li>
</ul>
</li>
</ol>
<hr />
<h2 id="4-rds-생성-및-고가용성-데이터베이스-인프라-구축">4. RDS 생성 및 고가용성 데이터베이스 인프라 구축</h2>
<p>AWS RDS(MySQL)를 프라이빗 서브넷 영역에 배치하는 과정.</p>
<hr />
<h3 id="41-rds-데이터베이스-보안-그룹sg-생성">4.1 RDS 데이터베이스 보안 그룹(SG) 생성</h3>
<p>데이터베이스의 보안을 위해 외부 인터넷으로부터의 접근을 원천 차단하고, 오직 프라이빗 WAS(Spring) 서버와 관리자(Bastion)로부터의 접근만 허용하도록 보안 그룹을 설정한다.</p>
<ol>
<li><p><strong>VPC 관리 콘솔</strong> -&gt; <strong>[보안 그룹]</strong> -&gt; <strong>[보안 그룹 생성]</strong>을 클릭한다.</p>
</li>
<li><p><strong>기본 상세 정보</strong> 설정을 다음과 같이 구성한다:</p>
<ul>
<li><strong>보안 그룹 이름</strong>: <code>bootcamp-rds-sg</code></li>
<li><strong>설명</strong>: <code>Security Group for Private RDS MySQL</code></li>
<li><strong>VPC</strong>: <code>bootcamp-vpc</code> 선택</li>
</ul>
</li>
<li><p><strong>인바운드 규칙(Inbound Rules)</strong>: </p>
<ul>
<li><strong>유형</strong>: <code>MYSQL/Aurora</code> (3306 포트)</li>
<li><strong>소스</strong>: <code>0.0.0.0/0</code></li>
</ul>
</li>
<li><p>하단의 <strong>[보안 그룹 생성]</strong>을 클릭한다.</p>
</li>
</ol>
<hr />
<h3 id="42-rds-db-서브넷-그룹-생성">4.2 RDS DB 서브넷 그룹 생성</h3>
<p>RDS 인스턴스가 고가용성을 유지하며 격리된 프라이빗 영역에 배치될 수 있도록 서브넷들을 하나로 묶는 그룹을 정의한다.</p>
<ol>
<li><strong>RDS 관리 콘솔</strong> -&gt; 좌측 메뉴에서 <strong>[서브넷 그룹]</strong> -&gt; <strong>[DB 서브넷 그룹 생성]</strong>을 클릭한다.</li>
<li><strong>서브넷 그룹 상세 정보</strong>를 입력한다:<ul>
<li><strong>이름</strong>: <code>bootcamp-db-subnet-group</code></li>
<li><strong>설명</strong>: <code>Subnet group for Multi-AZ RDS</code></li>
<li><strong>VPC</strong>: <code>bootcamp-vpc</code> 선택</li>
</ul>
</li>
<li><strong>서브넷 추가</strong> 영역을 다음과 같이 설정한다:<ul>
<li><strong>가용 영역(AZ)</strong>: <code>ap-northeast-2a</code> 및 <code>ap-northeast-2b</code> 둘 다 체크</li>
<li><strong>서브넷</strong>: 프라이빗 서브넷에 해당하는 CIDR인 <code>10.10.11.0/24</code> 및 <code>10.10.12.0/24</code>를 각각 선택하여 추가한다.</li>
</ul>
</li>
<li>하단의 <strong>[생성]</strong>을 클릭한다.</li>
</ol>
<hr />
<h3 id="43-rds-mysql-인스턴스-생성-다중-az-고가용성-적용">4.3 RDS MySQL 인스턴스 생성 (다중 AZ 고가용성 적용)</h3>
<p>실제 데이터베이스 인스턴스를 다중 AZ 배포 모드로 생성하여 운영 환경의 가용성을 충족한다.</p>
<ol>
<li><strong>RDS 관리 콘솔</strong> -&gt; <strong>[데이터베이스]</strong> -&gt; <strong>[데이터베이스 생성]</strong>을 클릭한다.</li>
<li><strong>데이터베이스 생성 방식 및 엔진 옵션</strong> 설정:<ul>
<li><strong>엔진 유형</strong>: <code>MySQL</code> 선택</li>
<li><strong>데이터베이스 생성 방식</strong>: <code>전체구성</code> 선택   </li>
<li><strong>템플릿</strong>: <code>샌드박스</code> 선택 </li>
</ul>
</li>
<li><strong>가용성 및 내구성 (핵심 설정)</strong>:<ul>
<li><strong>[단일 AZ DB 인스턴스 배포(인스턴스1개)]</strong> 옵션을 선택한다.</li>
</ul>
</li>
<li><strong>설정 및 인스턴스 구성</strong>:<ul>
<li><strong>DB 인스턴스 식별자</strong>: <code>bootcamp-database</code></li>
<li><strong>마스터 사용자 이름</strong>: <code>admin</code></li>
<li><strong>자격 증명 관리</strong>: <code>자체 관리</code></li>
<li><strong>마스터 암호</strong>: 임의 작성</li>
<li><strong>인스턴스 구성</strong>: <code>db.t3.micro</code></li>
</ul>
</li>
<li><strong>연결 (Connectivity) 설정</strong>:<ul>
<li><strong>컴퓨팅 리소스</strong>: <code>EC2 컴퓨팅 리소스에 연결 안 함</code> 유지</li>
<li><strong>VPC</strong>: <code>bootcamp-vpc</code></li>
<li><strong>DB 서브넷 그룹</strong>: <code>bootcamp-db-subnet-group</code> 자동 지정 확인</li>
<li><strong>퍼블릭 액세스</strong>: <strong>[아니요]</strong> 선택 (외부 인터넷 노출 방지)</li>
<li><strong>기존 VPC 보안 그룹</strong>: 기존 <code>default</code>를 제거하고, 방금 생성한 <strong><code>bootcamp-rds-sg</code></strong>를 선택한다.</li>
<li><strong>가용 영역</strong>: <code>기본 설정 없음</code> (AWS가 가용 영역 A와 B에 주/대기 DB를 적절히 분산 배치함)</li>
</ul>
</li>
<li><strong>추가 구성</strong> -&gt; <strong>데이터베이스 옵션</strong>:<ul>
<li><strong>최초 데이터베이스 이름</strong>: <code>testdb</code> (필요시 입력)</li>
</ul>
</li>
<li>하단의 <strong>[데이터베이스 생성]</strong>을 클릭한다. (생성 완료까지 약 5~10분 소요)</li>
</ol>
<hr />
<h2 id="5-spring-애플리케이션-생성-및-멀티-az-기반-프라이빗-배포">5. Spring 애플리케이션 생성 및 멀티 AZ 기반 프라이빗 배포</h2>
<p>프라이빗 서브넷 A와 B에 각각 Spring Boot 애플리케이션을 구동할 EC2 인스턴스를 생성하고, 앞서 생성한 RDS MySQL 데이터베이스와 연동하여 서비스를 배포하는 과정</p>
<hr />
<hr />
<h3 id="51-bastion-호스트를-통한-사설-접속-및-java-환경-구성">5.1 Bastion 호스트를 통한 사설 접속 및 Java 환경 구성</h3>
<p><strong>Bastion 호스트</strong>를 통해 각 WAS의 사설 ip로 접근하여 각 인스턴스에 JDK 설치</p>
<ol>
<li><p><strong>로컬 환경에서 Bastion 호스트로 SSH 접속</strong>:</p>
<pre><code class="language-bash">ssh -i &quot;bootcamp-key.pem&quot; ec2-user@&lt;BASTION_PUBLIC_IP&gt;</code></pre>
</li>
<li><p><strong>Bastion 내부에서 bootcamp-was-a 및 b로 교차 사설 접속</strong>:</p>
<pre><code class="language-bash"># bootcamp-was-a 접속 예시
ssh -i &quot;bootcamp-key.pem&quot; ec2-user@&lt;WAS_A_PRIVATE_IP&gt;

# bootcamp-was-b 접속 예시
ssh -i &quot;bootcamp-key.pem&quot; ec2-user@&lt;WAS_B_PRIVATE_IP&gt;</code></pre>
</li>
<li><p><strong>Java SDK(JDK) 설치 (두 인스턴스 공통 수행)</strong>:
Spring Boot 구동에 필요한 Java 환경을 설치한다.</p>
<pre><code class="language-bash">sudo apt update
sudo sudo apt install openjdk-21-jdk -y
java -version</code></pre>
</li>
</ol>
<hr />
<h3 id="52-spring-boot-빌드-파일jar-전송-및-고가용성-구동">5.2 Spring Boot 빌드 파일(JAR) 전송 및 고가용성 구동</h3>
<p>로컬 PC 또는 Bastion에서 빌드된 Spring Boot JAR 파일을 각 프라이빗 인스턴스로 복사하고 데이터베이스 연결 설정을 주입하여 백그라운드에서 구동한다. 
Spring 프로젝트는 기존에 만든 프로젝틀 사용한다.</p>
<ol>
<li><p><strong>Github로부터 SpringBoot 프로젝트 clone 하기</strong></p>
<pre><code class="language-bash">git clone &quot;git 주소&quot;</code></pre>
</li>
<li><p><strong>application.yml 파일 수정하기</strong></p>
<pre><code class="language-bash">BASH
cd &quot;Spring 프로젝트 폴더&quot;/src/main/resources/
vim application.yml</code></pre>
<pre><code class="language-yaml">YAML
datasource:
   url: jdbc:mysql://{AWS RDS 엔드포인트}:3306/testdb?serverTimezone=Asia/Seoul&amp;characterEncoding=UTF-8&amp;allowPublicKeyRetrieval=true&amp;useSSL=false
   driver-class-name: com.mysql.cj.jdbc.Driver
   username: admin
   password: {설정한 비빌번호}   </code></pre>
</li>
<li><p><strong>빌드해서 SpringBoot 서버 실행시키기</strong></p>
<pre><code class="language-bash">$ cd aws_springboot_mysql
$ chmod +x gradlew
$ ./gradlew clean build -x test
$ cd build/libs
$ sudo nohup java -jar &quot;build 결과물&quot;.jar &amp;
$ sudo lsof -i :80</code></pre>
</li>
</ol>
<hr />
<h2 id="6-elbapplication-load-balancer-추가-및-고가용성-외부-진입점-구축">6. ELB(Application Load Balancer) 추가 및 고가용성 외부 진입점 구축</h2>
<p>AWS의 <strong>Application Load Balancer (ALB)</strong>를 활용하여 멀티 가용 영역(Multi-AZ) 전체에 걸친 트래픽 라우팅 및 상태 검사(Health Check) 체계를 완성한다.</p>
<hr />
<h3 id="61-로드-밸런서-전용-보안-그룹sg-생성">6.1 로드 밸런서 전용 보안 그룹(SG) 생성</h3>
<p>외부 모든 사용자로부터의 HTTP 웹 트래픽을 허용하되, 로드 밸런서 자체의 보안을 정의하기 위해 독립된 보안 그룹을 생성한다.</p>
<ol>
<li><strong>VPC 관리 콘솔</strong> -&gt; <strong>[보안 그룹]</strong> -&gt; <strong>[보안 그룹 생성]</strong>을 클릭한다.</li>
<li><strong>기본 상세 정보</strong> 설정을 다음과 같이 구성한다:<ul>
<li><strong>보안 그룹 이름</strong>: <code>bootcamp-elb-sg</code></li>
<li><strong>설명</strong>: <code>Security Group for Public Application Load Balancer</code></li>
<li><strong>VPC</strong>: <code>bootcamp-vpc</code> 선택</li>
</ul>
</li>
<li><strong>인바운드 규칙(Inbound Rules)</strong>을 추가한다:<ul>
<li><strong>유형</strong>: <code>HTTP</code> (80번 포트)</li>
<li><strong>소스</strong>: <code>Anywhere-IPv4 (0.0.0.0/0)</code> (모든 외부 인터넷 유입 허용)</li>
</ul>
</li>
<li>하단의 <strong>[보안 그룹 생성]</strong>을 클릭한다.</li>
</ol>
<hr />
<h3 id="62-프라이빗-was-보안-그룹-규칙-추가-보안-체이닝-결합">6.2 프라이빗 WAS 보안 그룹 규칙 추가 (보안 체이닝 결합)</h3>
<ol>
<li><p><strong>VPC 콘솔</strong> -&gt; <strong>[보안 그룹]</strong> -&gt; <strong><code>bootcamp-private-was-sg</code></strong>를 선택한다.</p>
</li>
<li><p>하단의 <strong>[인바운드 규칙 편집]</strong>을 클릭한다.</p>
</li>
<li><p><strong>[규칙 추가]</strong>를 눌러 다음과 같이 구성을 연계한다:</p>
<ul>
<li><strong>유형</strong>: `HTTP</li>
<li><strong>포트 범위</strong>: <code>80</code></li>
<li><strong>소스</strong>: <code>0.0.0.0/0</code></li>
<li><strong>유형</strong>: <code>HTTPS</code></li>
<li><strong>포트 범위</strong>: <code>443</code></li>
<li><strong>소스</strong>: <code>0.0.0.0/0</code></li>
</ul>
</li>
<li><p><strong>[규칙 저장]</strong>을 완료한다.</p>
</li>
</ol>
<hr />
<h3 id="63-로드-밸런서-대상-그룹target-group-생성">6.3 로드 밸런서 대상 그룹(Target Group) 생성</h3>
<p>로드 밸런서가 트래픽을 전달할 목적지 호스트들과 서비스 포트, 상태 검사 경로를 정의한다.</p>
<ol>
<li><strong>EC2 관리 콘솔</strong> -&gt; 좌측 하단 메뉴에서 <strong>[대상 그룹 (Target Groups)]</strong> -&gt; <strong>[대상 그룹 생성]</strong>을 클릭한다.</li>
<li><strong>기본 구성</strong> 설정을 다음과 같이 진행한다:<ul>
<li><strong>대상 유형 선택</strong>: <code>인스턴스 (Instances)</code> 선택</li>
<li><strong>대상 그룹 이름</strong>: <code>bootcamp-was-tg</code></li>
<li><strong>프로토콜</strong>: <code>HTTP</code></li>
<li><strong>포트</strong>: <code>80</code></li>
<li><strong>VPC</strong>: <code>bootcamp-vpc</code> 선택</li>
</ul>
</li>
<li><strong>상태 검사 (Health Check)</strong> 설정:<ul>
<li><strong>상태 검사 프로토콜</strong>: <code>HTTP</code></li>
<li><strong>상태 검사 경로</strong>: <code>/health</code> (애플리케이션의 헬스체크 엔드포인트 경로 입력)</li>
</ul>
</li>
<li><strong>[다음]</strong> 버튼을 클릭한다.</li>
<li><strong>대상 등록 (Register targets)</strong>:<ul>
<li>가용 영역 A와 B에 각각 배치되어 가동 중인 <code>bootcamp-was-a</code>와 <code>bootcamp-was-b</code> 인스턴스 2개를 모두 체크한다.</li>
<li><strong>[아래에 보류 중인 것으로 포함 (Include as pending below)]</strong> 버튼을 클릭하여 포트 8080으로 대상을 매핑한다.</li>
</ul>
</li>
<li>하단의 <strong>[대상 그룹 생성]</strong>을 클릭하여 완료한다.</li>
</ol>
<hr />
<h3 id="64-alb-application-load-balancer-생성-및-외부-연동">6.4 ALB (Application Load Balancer) 생성 및 외부 연동</h3>
<p>인터넷 접점에 위치하여 실질적인 라우팅을 수행할 로드 밸런서를 생성하고 물리 영역과 논리 영역을 바인딩한다.</p>
<ol>
<li><strong>EC2 관리 콘솔</strong> -&gt; 좌측 메뉴에서 <strong>[로드 밸런서 (Load Balancers)]</strong> -&gt; <strong>[로드 밸런서 생성]</strong>을 클릭한다.</li>
<li>로드 밸런서 유형 중 <strong>Application Load Balancer</strong> 아래의 <strong>[생성]</strong> 버튼을 클릭한다.</li>
<li><strong>기본 구성</strong>:<ul>
<li><strong>로드 밸런서 이름</strong>: <code>bootcamp-alb</code></li>
<li><strong>체계 (Scheme)</strong>: <code>인터넷 경계형 (Internet-facing)</code> (외부 인터넷 서비스 목적)</li>
<li><strong>IP 주소 유형</strong>: <code>IPv4</code></li>
</ul>
</li>
<li><strong>네트워크 매핑 (Network mapping - 중요)</strong>:<ul>
<li><strong>VPC</strong>: <code>bootcamp-vpc</code> 선택</li>
<li><strong>가용 영역 및 서브넷 매핑</strong>:<ul>
<li><code>ap-northeast-2a</code> 체크 -&gt; <strong><code>bootcamp-public-subnet-a</code></strong> 선택</li>
<li><code>ap-northeast-2b</code> 체크 -&gt; <strong><code>bootcamp-public-subnet-b</code></strong> 선택</li>
<li><em>(※ 외부 사용자가 진입하는 통로이므로 반드시 외부 통신이 유효한 퍼블릭 서브넷 2곳을 교차 지정해야 함)</em></li>
</ul>
</li>
</ul>
</li>
<li><strong>보안 그룹 (Security groups)</strong>:<ul>
<li>기본 설정된 <code>default</code>를 제거하고, 방금 생성한 <strong><code>bootcamp-elb-sg</code></strong>를 지정한다.</li>
</ul>
</li>
<li><strong>리스너 및 라우팅 (Listeners and routing)</strong>:<ul>
<li><strong>프로토콜</strong>: <code>HTTP</code> / <strong>포트</strong>: <code>80</code></li>
<li><strong>기본 작업 (Forward)</strong>: 방금 생성한 대상 그룹인 <strong><code>bootcamp-was-g</code></strong>를 지정한다.</li>
</ul>
</li>
<li>하단의 <strong>[로드 밸런서 생성]</strong>을 클릭한다. (프로비저닝 완료까지 약 2~3분 소요)</li>
</ol>
<hr />
<h3 id="65-외부-접속-테스트-및-고가용성-검증">6.5 외부 접속 테스트 및 고가용성 검증</h3>
<p>생성 완료 후 상태가 <code>Active</code>로 변경되면, 완전한 멀티 AZ 고가용성 웹 서비스의 작동 여부를 검증한다.</p>
<ol>
<li><strong>ALB DNS 이름 확인</strong>:<ul>
<li>생성된 <code>bootcamp-alb</code>를 선택한 후 상세 정보 창에서 <strong>DNS 이름</strong>(예: <code>bootcamp-alb-XXXXXX.ap-northeast-2.elb.amazonaws.com</code>)을 복사한다.</li>
</ul>
</li>
<li><strong>웹 브라우저 접속</strong>:<ul>
<li>주소창에 복사한 DNS 이름을 입력하여 Spring Boot 애플리케이션 화면이 정상적으로 출력되는지 확인한다.</li>
</ul>
</li>
<li><strong>helth 체크</strong>:<ul>
<li>이 과정은 Spring boot에 healt 체크 기능이 존재하는 겨웅에만 진행한다</li>
<li>Talend API Tester 접속</li>
<li>Add a request에서 요청 작성<ul>
<li>METHOD: <code>GET</code></li>
<li>SCHEME: <code>http://{DNS 이름}/health</code></li>
</ul>
</li>
</ul>
</li>
</ol>
