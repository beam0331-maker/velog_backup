<h2 id="s3-개요-및-핵심-구성요소">S3 개요 및 핵심 구성요소</h2>
<hr />
<h3 id="1-amazon-s3-개요">1. Amazon S3 개요</h3>
<h4 id="11-s3의-특징">1.1 S3의 특징</h4>
<ul>
<li>AWS에서 제공하는 객체(Object) 스토리지 서비스이다.<ul>
<li>글로벌 서비스이며, 데이터는 지정된 리전에 저장된다.</li>
<li>무제한 용량을 제공하며, 데이터 증가에 따라 자동으로 확장된다.<ul>
<li>사용한 만큼만 비용이 과금되는 구조이다.</li>
</ul>
</li>
<li>파일 보관만 가능하며, 별도의 어플리케이션 설치는 불가능하다.</li>
<li>99.999999999%의 내구성 및 99.99%의 가용성을 제공하도록 설계되었다.</li>
<li>버전관리, 암호화, 웹 호스팅 등 다양한 추가 기능을 포함한다.</li>
<li>주기적인 복제를 진행하며, 파일 삭제 방지 기능 및 IAM을 이용한 권한 관리가 적용된다.</li>
</ul>
</li>
</ul>
<h4 id="12-주요-사용-사례">1.2 주요 사용 사례</h4>
<ul>
<li>쇼핑몰 이미지와 같은 웹 사이트 정적 파일 보관에 사용된다.</li>
<li>로그 저장 및 백업/아카이브 용도로 활용된다.<ul>
<li>빅데이터 분석을 위한 데이터 레이크(Data Lake) 구성을 위해 사용된다.</li>
</ul>
</li>
</ul>
<hr />
<h3 id="2-s3-핵심-구성요소">2. S3 핵심 구성요소</h3>
<h4 id="21-bucket-버킷">2.1 Bucket (버킷)</h4>
<ul>
<li>객체를 저장하는 최상위 컨테이너 역할을 한다.<ul>
<li>전 세계에서 이름이 유일해야만 한다.</li>
</ul>
</li>
</ul>
<h4 id="22-object-객체-및-key-키">2.2 Object (객체) 및 Key (키)</h4>
<ul>
<li><strong>Object</strong>: S3에 실제 저장되는 데이터(파일)를 의미한다.<ul>
<li>파일 데이터, 메타데이터, Key, Storage Class 등으로 구성된다.</li>
</ul>
</li>
<li><strong>Key</strong>: 객체의 이름이자 논리적인 경로를 의미한다.<ul>
<li>예시로 <code>images/product1.png</code>, <code>backup/2026/db.sql</code> 등이 있다.</li>
</ul>
</li>
</ul>
<hr />
<h3 id="3-s3-보안-및-권한-관리">3. S3 보안 및 권한 관리</h3>
<h4 id="31-s3-보안-개념">3.1 S3 보안 개념</h4>
<ul>
<li>모든 S3 버킷은 생성 시 기본적으로 Private(비공개) 상태로 설정된다.<ul>
<li>보안 설정은 버킷 단위와 객체 단위로 구성할 수 있다.</li>
<li>버킷 정책(Bucket Policy), Access Control List(ACL, 과거 객체 단위 권한 방법), 서버 측 암호화, 액세스 로그 생성 등을 지원한다.</li>
</ul>
</li>
</ul>
<h4 id="32-권한-제어-요소">3.2 권한 제어 요소</h4>
<ul>
<li>누가(Principal) 어떤 리소스(Resource)에 무엇을(Action) 어떤 조건(Condition)에서 할 수 있는가를 제어한다.<ul>
<li><strong>IAM Policy</strong>: 사용자, 그룹, 역할에 붙는 주체 중심 정책으로, 해당 주체가 S3에서 무엇을 할 수 있는지 정의한다.</li>
<li><strong>Bucket Policy</strong>: 버킷 자체에 붙는 리소스 기반 정책으로, 버킷이 누구에게 무엇을 허용/거부할 것인지 정의한다.</li>
<li><strong>Block Public Access (퍼블릭 액세스 차단)</strong>: S3 보안의 가장 중요한 안전장치 기능이다.<ul>
<li>퍼블릭으로 설정된 다른 모든 정책보다 최우선 적용되어 접근을 차단한다.</li>
</ul>
</li>
<li><strong>권한 평가</strong>: 접근 요청 시 IAM 정책과 버킷 정책을 함께 평가한다.<ul>
<li>명시적 Deny(거부)가 있으면 실패하고 둘 다 문제가 없어야 성공한다.</li>
</ul>
</li>
</ul>
</li>
</ul>

<h2 id="딥다이브-웹-호스팅-아키텍처-관점에서-본-s3-vs-ec2">딥다이브: 웹 호스팅 아키텍처 관점에서 본 S3 vs EC2</h2>
<p>강의 중에 S3를 통해 정적 웹 호스팅이 가능하다는 것을 알게되었다. 가상 서버를 띄워 배포하는 전통적인 EC2 방식과, S3 웹 호스팅의 차이점에 대해서 알아보자</p>
<h3 id="1-aws-s3-정적-웹-호스팅의-장점과-한계">1. AWS S3 정적 웹 호스팅의 장점과 한계</h3>
<ul>
<li><strong>장점: 가성비와 무관리</strong><ul>
<li>웹 서버(ex. Nginx) 설치나 OS 보안 패치 등 서버 관리 자원이 필요하지 않다.</li>
<li>트래픽 폭증 시에도 AWS 인프라가 자동으로 관리한다.</li>
<li>사용량 기반 과금 구조 덕분에 고정 비용이 거의 발생하지 않는다.</li>
</ul>
</li>
<li><strong>한계</strong><ul>
<li>서버 사이드 스크립트 실행이 불가능하여 순수 정적 파일만 처리할 수 있다.</li>
<li>라우팅 제어가 까다롭다.<h3 id="2-ec2-배포-방식과의-차이">2. EC2 배포 방식과의 차이</h3>
</li>
</ul>
</li>
<li>완전한 가상 서버를 임대하는 방식. 백엔드 API 연동, 동적 렌더링(SSR), 세밀한 Nginx 라우팅 규칙 설정을 자유롭게 커스터마이징할 수 있다.</li>
<li>트래픽 변화에 대응하려면 로드 밸런서(ALB) 및 오토 스케일링 그룹을 직접 구성해야 하므로 아키텍처 복잡도가 상승한다.<ul>
<li>서버 인스턴스가 유지되는 시간 동안 트래픽 유무와 무관하게 고정 비용이 지속적으로 청구된다.<h3 id="3-실무적-활용-시나리오">3. 실무적 활용 시나리오</h3>
</li>
</ul>
</li>
<li><strong>S3 웹 호스팅</strong>: React나 Vue.js 기반 모던 프론트엔드 SPA(Single Page Application) 배포에 적극적으로 채택된다.    .</li>
<li><strong>EC2 웹 배포</strong>: 백엔드 API가 통합된 애플리케이션처럼, 서버 측 로직과 세밀한 인프라 제어가 필요한 경우에 적합하다.</li>
</ul>
<h3 id="4-s3-vs-ec2-핵심-인프라-요약">4. S3 vs EC2 핵심 인프라 요약</h3>
<table>
<thead>
