<h3 id="1-요청-위임request-delegation-전략">1. 요청 위임(Request Delegation) 전략</h3>
<p>서블릿(Controller)과 JSP(View)를 분리할 때, request를 어떻게 넘기느냐에 따라 데이터의 유효 범위가 결정된다</p>
<p><strong>1.1. Forward (포워드)</strong>
서버 내부에서 이동하므로 <code>request</code>와 <code>response</code> 객체가 공유되어 데이터 전달이 용이하지만, URL 주소가 변하지 않는다.</p>
<pre><code class="language-java">// 1. request scope에 데이터 저장
request.setAttribute(&quot;key&quot;, &quot;공유 데이터&quot;);

// 2. 서버 내부에서 target.jsp로 제어 위임 (URL 유지)
request.getRequestDispatcher(&quot;target.jsp&quot;).forward(request, response);</code></pre>
<p><strong>1.2. Redirect (리다이렉트)</strong>
서버가 브라우저에게 새로운 주소로 다시 요청하라고 명령한다. 브라우저가 새로운 요청을 발생시키므로 기존 <code>request</code> 데이터는 소멸되며 URL 주소가 변경된다.</p>
<pre><code class="language-java">// 브라우저에게 새로운 경로로 다시 접속하라고 응답 (URL 변경)
response.sendRedirect(&quot;target.jsp&quot;);</code></pre>
<hr />
<h3 id="2-상태-유지-기법-http-세션-관리">2. 상태 유지 기법: HTTP 세션 관리</h3>
<p>HTTP 프로토콜의 무상태성(Stateless)을 해결하기 위해 서버의 메모리를 사용하여 사용자 정보를 저장하는 기법이다.</p>
<p><strong>2.1. 세션의 생명주기</strong></p>
<pre><code class="language-java">// [Servlet] 세션 생성 및 데이터 저장
HttpSession session = request.getSession();
session.setAttribute(&quot;loginUser&quot;, &quot;홍길동&quot;);

// [Servlet] 세션 무효화 (로그아웃)
session.invalidate();</code></pre>
<pre><code class="language-jsp">&lt;%-- [JSP] 세션 데이터 조회 및 출력 --%&gt;
&lt;%
    // session 내장 객체를 통해 저장된 데이터 획득
    String user = (String)session.getAttribute(&quot;loginUser&quot;);
%&gt;
&lt;h1&gt;로그인 정보&lt;/h1&gt;
사용자명: &lt;%= (user != null) ? user : &quot;로그인 필요&quot; %&gt;</code></pre>
<ul>
<li><strong>데이터 life cycle:</strong> 브라우저가 닫히기 전까지 데이터를 유지할 수 있다. 로그인같이 life cycle이 브라우저와 같은 경우에 유용하다.</li>
</ul>

<h3 id="3-jsp-동작-원리와-주요-지시자-구성">3. JSP 동작 원리와 주요 지시자 구성</h3>
<p>JSP는 실제 실행 시 웹 컨테이너에 의해 서블릿 클래스로 변환되어 동작한다.</p>
<p><strong>3.1. JSP 실행 3단계</strong></p>
<ul>
<li><strong>Translation (변환):</strong> <code>.jsp</code> 파일을 자바 파일(<code>.java</code>)로 생성한다.</li>
<li><strong>Compilation (컴파일):</strong> 자바파을 바이트코드(<code>.class</code>)로 변환한다.</li>
<li><strong>Execution (실행):</strong> 컴파일된 클래스를 통해 요청을 처리하고 결과를 응답한다.</li>
</ul>
<p><strong>3.2. 주요 지시자(Directive)의 동작 방식과 활용</strong>
지시자는 <code>&lt;%@ ... %&gt;</code> 구문을 사용하여 웹 컨테이너에게 해당 페이지를 어떻게 처리할지 사전 지침을 내리는 역할을 한다.</p>
<ul>
<li><p><strong>Page 지시자 (<code>&lt;%@ page ... %&gt;</code>):</strong> JSP 페이지에 대한 전반적인 환경 설정을 담당한다.</p>
<ul>
<li><strong>문서 타입 및 인코딩 지정:</strong> 
<code>&lt;%@ page contentType=&quot;text/html; charset=UTF-8&quot; %&gt;</code>과 같이 작성하여 브라우저가 문서를 올바르게 렌더링하도록 돕는다.</li>
<li><strong>클래스 import:</strong> 
자바 클래스를 사용해야 할 때 <code>&lt;%@ page import=&quot;java.util.List, com.dto.BoardDTO&quot; %&gt;</code> 형태로 선언하여 클래스 경로를 확보한다.</li>
</ul>
</li>
<li><p><strong>Include 지시자 (<code>&lt;%@ include file=&quot;...&quot; %&gt;</code>):</strong> 여러 페이지에서 공통으로 쓰이는 UI를 재사용하기 위해 사용한다.</p>
</li>
</ul>

<h3 id="4-mvc-아키텍처-및-crud-구현">4. MVC 아키텍처 및 CRUD 구현</h3>
<p>MVC 아키텍처는 &quot;모든 요청은 컨트롤러(Servlet)가 먼저 받는다&quot;는 원칙을 가진다.</p>
<ul>
<li><strong>Controller:</strong> 요청 파라미터 수집 및 서비스 계층 호출.</li>
<li><strong>Service:</strong> 비즈니스 로직 처리 및 트랜잭션(Commit/Rollback) 관리.</li>
<li><strong>DAO:</strong> MyBatis를 이용한 DB 연동 및 쿼리 실행.</li>
<li><strong>의사 결정 기준:</strong> 단순 데이터 조회는 Forward를, 데이터 변경(DML) 후 목록으로 돌아가는 경우는 Redirect를 선택한다.</li>
</ul>

<h3 id="5-계층별-핵심-구현-코드-annotated-code">5. 계층별 핵심 구현 코드 (Annotated Code)</h3>
<p><strong>[로그인 처리와 세션 바인딩]</strong></p>
<pre><code class="language-java">public class LoginServlet extends HttpServlet {
    protected void doGet(HttpServletRequest request, HttpServletResponse response) throws ServletException, IOException {
        String userid = request.getParameter(&quot;userid&quot;);

        HttpSession session = request.getSession();
        session.setAttribute(&quot;userid&quot;, userid);
        session.setAttribute(&quot;username&quot;, &quot;관리자&quot;);

        // 상태 변경(로그인) 후 페이지 이동을 위해 Redirect 사용
        response.sendRedirect(&quot;loginSuccess.jsp&quot;);
    }
}</code></pre>
<p><strong>[게시글 수정과 데이터 무결성 보장]</strong></p>
<pre><code class="language-java">public class BoardUpdateServlet extends HttpServlet {
    protected void doGet(HttpServletRequest request, HttpServletResponse response) throws ServletException, IOException {
        BoardService service = new BoardServiceImpl();
        service.setDao(new BoardDAO());

        BoardDTO dto = new BoardDTO();
        dto.setNum(Integer.parseInt(request.getParameter(&quot;num&quot;)));
        dto.setTitle(request.getParameter(&quot;title&quot;));

        int result = service.update(dto);

        // 데이터 수정 후 중복 요청 방지를 위해 Redirect 수행
        response.sendRedirect(&quot;BoardListServlet&quot;);
    }
}</code></pre>
<p><strong>[서비스 계층의 트랜잭션 제어]</strong></p>
<pre><code class="language-java">public class BoardServiceImpl implements BoardService {
    @Override
    public int delete(int num) {
        // 단일 세션으로 트랜잭션 범위를 설정
        SqlSession session = MySqlSessionFactory.getSession();
        int result = 0;
        try {
            result = dao.delete(session, num);
            // 원자성 보장: 삭제 성공 시에만 최종 커밋 수행
            if(result == 1) {
                session.commit();
            }
        } finally {
            // 커넥션 풀 자원 반납
            session.close();
        }
        return result;
    }
}</code></pre>
