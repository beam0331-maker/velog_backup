<h3 id="1-파일-및-디렉터리-기본-관리">1. 파일 및 디렉터리 기본 관리</h3>
<h4 id="1-1-파일-생성-및-시간-조작-touch">1-1. 파일 생성 및 시간 조작 (touch)</h4>
<ul>
<li><strong>문법 :</strong> <code>touch [옵션]... &lt;파일명&gt;...</code></li>
<li><strong><code>touch</code> 기본기 :</strong> 파일이 존재하지 않으면 빈 파일을 생성하고, 존재하면 내용은 유지한 채 타임스탬프만 현재로 갱신한다.</li>
</ul>
<table>
<thead>
<tr>
<th align="left">옵션</th>
<th align="left">상세 설명</th>
</tr>
</thead>
<tbody><tr>
<td align="left"><strong><code>-t</code></strong></td>
<td align="left">현재 시간이 아닌 사용자가 지정한 특정 시간(YYYYMMDDhhmm)으로 수정 시간을 조작gksek</td>
</tr>
<tr>
<td align="left"><strong><code>-c</code></strong></td>
<td align="left">지정한 파일이 존재하지 않더라도 새로운 빈 파일을 억지로 생성하지 않음</td>
</tr>
</tbody></table>
<h4 id="1-2-디렉터리-생성-mkdir">1-2. 디렉터리 생성 (mkdir)</h4>
<ul>
<li><strong>문법 :</strong> <code>mkdir [옵션]... &lt;디렉터리명&gt;...</code></li>
<li><strong>계층적 생성 원리 :</strong> 중간 경로 폴더가 없더라도 에러 없이 한 번에 생성하며 인프라 구축 시 멱등성을 보장한다.</li>
</ul>
<table>
<thead>
<tr>

<th align="left">상세 설명</th>
</tr>
</thead>

<td align="left"><strong><code>-p</code></strong></td>
<td align="left">상위 디렉터리가 없을 경우 하위 폴더까지 끊기지 않고 한 번에 쭉 생성함</td>
</tr>
<tr>
<td align="left"><strong><code>-v</code></strong></td>
<td align="left">디렉터리가 성공적으로 만들어진 과정을 터미널에 메시지로 상세히 출력함</td>
</tr>
</tbody></table>
<h4 id="1-3-파일-및-디렉터리-복사-cp">1-3. 파일 및 디렉터리 복사 (cp)</h4>
<ul>
<li><strong>문법 :</strong> <code>cp [옵션]... &lt;원본&gt;... &lt;복사될 위치 및 이름&gt;</code></li>
<li><strong>속성 보존 및 연쇄 복사 :</strong> 원본의 속성을 유지하거나 폴더 단위로 관리하는 명령어이다.</li>
</ul>
<table>
<thead>
<tr>
<th align="left">옵션</th>
<th align="left">상세 설명</th>
</tr>
</thead>
<tbody><tr>
<td align="left"><strong><code>-r</code></strong></td>
<td align="left">디렉터리를 복사할 때 하위에 포함된 모든 서브 디렉터리와 파일을 통째로 복사함</td>
</tr>
<tr>
<td align="left"><strong><code>-p</code></strong></td>
<td align="left">원본 파일의 권한, 소유자, 타임스탬프를 변형시키지 않고 원형 그대로 보존함</td>
</tr>
<tr>
<td align="left"><strong><code>-i</code></strong></td>
<td align="left">동일한 이름의 파일이 있어 덮어쓰기 상황이 발생할 경우 사용자에게 미리 실행 여부를 물어봄</td>
</tr>
</tbody></table>
<h4 id="1-4-파일-및-디렉터리-이동-mv">1-4. 파일 및 디렉터리 이동 (mv)</h4>
<ul>
<li><strong>문법 :</strong> <code>mv [옵션]... &lt;원본&gt;... &lt;이동시킬 위치 및 이름&gt;</code></li>
<li><strong>이동 및 이름 변경 :</strong> 동일 디스크 내에서는 실제 데이터를 옮기지 않고 디렉토리 엔트리를 수정하므로 처리 속도가 빠르다. 단 디스크가 다르면 실제 데이터 이동이 발생할 수 있다.</li>
</ul>
<table>
<thead>
<tr>
<th align="left">옵션</th>
<th align="left">상세 설명</th>
</tr>
</thead>
<tbody><tr>
<td align="left"><strong><code>-i</code></strong></td>
<td align="left">목적지에 동일한 파일이 있을 경우 덮어쓰기 여부를 사용자에게 확인받음</td>
</tr>
<tr>
<td align="left"><strong><code>-f</code></strong></td>
<td align="left">강제로 덮어쓰기를 수행함</td>
</tr>
<tr>
<td align="left"><strong><code>-n</code></strong></td>
<td align="left">목적지에 동일한 이름의 파일이 존재하면 기존 파일을 보호하기 위해 덮어쓰지 않고 이동을 취소함</td>
</tr>
<tr>
<td align="left"><strong><code>-u</code></strong></td>
<td align="left">원본 파일이 목적지 파일보다 최신 버전이거나 목적지에 파일이 없을 때만 선택적으로 덮어쓰고 이동함</td>
</tr>
<tr>
<td align="left"><strong><code>-v</code></strong></td>
<td align="left">파일이 어디로 이동하고 어떻게 이름이 바뀌었는지 상세 내역을 화면에 출력함</td>
</tr>
</tbody></table>

<h3 id="2-링크-파일과-파일-시스템-구조">2. 링크 파일과 파일 시스템 구조</h3>
<h4 id="2-1-리눅스의-파일-관리-단위-inode">2-1. 리눅스의 파일 관리 단위 (Inode)</h4>
<blockquote>
<p><strong>아이노드 (Inode) 개념</strong>
파일의 실제 데이터가 하드디스크 어디에 저장되어 있는지 가리키는 주소 번호이다.</p>
</blockquote>
<h4 id="2-2-하드-링크-vs-소프트링크-심볼릭-링크-상세-비교-ln">2-2. 하드 링크 vs 소프트링크 (심볼릭 링크) 상세 비교 (ln)</h4>
<ul>
<li><strong>문법 :</strong> <code>ln [옵션] &lt;원본 파일&gt; [생성할 링크 파일명]</code></li>
<li><strong>링크 생성 원리 :</strong> 원본 파일에 여러 개의 이름표를 붙여 파일 액세스 및 관리 효율을 극대화하는 기술이다.</li>
</ul>
<table>
<thead>
<tr>
<th align="left">비교 항목</th>
<th align="left">하드 링크 (<code>ln &lt;원본&gt; &lt;링크&gt;</code>)</th>
<th align="left">소프트링크 (심볼릭 링크) (<code>ln -s &lt;원본&gt; &lt;링크&gt;</code>)</th>
</tr>
</thead>
<tbody><tr>
<td align="left"><strong>Inode 번호</strong></td>
<td align="left">원본 파일과 완벽히 동일한 Inode 주소를 공유함</td>
<td align="left">원본 파일과 전혀 다른 새로운 고유 Inode를 생성함</td>
</tr>
<tr>
<td align="left"><strong>원본 삭제 시</strong></td>
<td align="left">데이터 주소가 유지되어 파일 사용 가능</td>
<td align="left">원본의 경로를 가리키므로 링크 파일이 빨갛게 고장 남 (Dangling)</td>
</tr>
<tr>
<td align="left"><strong>디렉터리 지원</strong></td>
<td align="left">구조적 무한 루프 방지를 위해 디렉터리에는 생성 불가능함</td>
<td align="left">파일뿐만 아니라 디렉터리(폴더)에도 자유롭게 생성 가능함</td>
</tr>
</tbody></table>

<h3 id="3-리눅스-고급-검색-도구와-파이프라인">3. 리눅스 고급 검색 도구와 파이프라인</h3>
<h4 id="3-1-조건별-파일-검색-find">3-1. 조건별 파일 검색 (find)</h4>
<ul>
<li><strong>문법 :</strong> <code>find [검색 경로]... [조건]... [-exec &lt;명령어&gt; {} \;]</code></li>
<li><strong>스마트 파일 추적 :</strong> 이름, 속성, 시간 등 다양한 조건으로 시스템을 스캔하고 즉시 실행을 연계한다.</li>
</ul>
<table>
<thead>
<tr>
<th align="left">조건 및 옵션</th>
<th align="left">실무 활용 상세 설명</th>
</tr>
</thead>
<tbody><tr>
<td align="left"><strong><code>-name</code></strong></td>
<td align="left">와일드카드(<code>*</code>)를 조합하여 특정 문자열과 이름이 일치하는 파일을 추적함</td>
</tr>
<tr>
<td align="left"><strong><code>-type</code></strong></td>
<td align="left">대상이 파일(<code>f</code>)인지 디렉터리(<code>d</code>)인지 종류를 명확히 한정지어 스캔함</td>
</tr>
<tr>
<td align="left"><strong><code>-mtime</code></strong></td>
<td align="left">특정 일수 이전에 수정된 파일을 찾음 (예: <code>+30</code>은 30일이 지난 파일을 의미)</td>
</tr>
<tr>
<td align="left"><strong><code>-exec</code></strong></td>
<td align="left">검색 조건에 부합하는 파일들을 대상으로 후속 명령(<code>rm</code>, <code>mv</code> 등)을 즉시 자동 실행함</td>
</tr>
</tbody></table>
<h4 id="3-2-텍스트-내용-검색-grep">3-2. 텍스트 내용 검색 (grep)</h4>
<ul>
<li><strong>문법 :</strong> <code>grep [옵션]... &lt;&quot;검색어&quot;&gt; [대상 파일명]...</code></li>
<li><strong>내용 및 오류 스캐너 :</strong> 파일 내부의 텍스트를 검사하거나 명령어 파이프라인의 필터로 강력하게 활용된다.</li>
</ul>
<table>
<thead>
<tr>
<th align="left">옵션</th>
<th align="left">실무 활용 상세 설명</th>
</tr>
</thead>

<td align="left"><strong><code>-i</code></strong></td>
<td align="left">검색어의 대소문자(A/a)를 엄격하게 구분하지 않고 모두 잡아냄</td>

<tr>
<td align="left"><strong><code>-n</code></strong></td>

</tr>
</tbody></table>
<h4 id="3-3-파이프를-이용한-명령어-릴레이-pipes">3-3. 파이프를 이용한 명령어 릴레이 (Pipes)</h4>
<ul>
<li><strong>문법 :</strong> <code>&lt;명령어 1&gt; | &lt;명령어 2&gt;</code></li>
<li><strong>바통 터치 (<code>|</code>) :</strong> 앞선 명령어의 출력 결과를 화면에 보이지 않고, 뒤에 오는 명령어의 입력으로 넘겨주는 통로 역할을 한다.</li>
<li><strong>조합 :</strong> <code>ps -ef | grep mysql</code> 처럼 방대한 출력물 중에서 원하는 특정 키워드만 필터링할 때 필수적이다.</li>
</ul>
<hr />
<h3 id="4-파일-아카이빙과-압축-컨텍스트">4. 파일 아카이빙과 압축 컨텍스트</h3>
<h4 id="4-1-파일-묶기와-압축의-분리-메커니즘">4-1. 파일 묶기와 압축의 분리 메커니즘</h4>
<ul>
<li><strong>파일 묶기 (<code>tar</code>) :</strong> 여러 개의 파일이나 디렉터리를 용량 변화 없이 단순히 하나의 묶음 파일(<code>.tar</code>)로 합치는 작업이다.</li>
<li><strong>파일 압축 (<code>gzip</code>) :</strong> 압축 작업(<code>.gz</code>)으로, 리눅스는 보통 <code>tar</code>로 먼저 묶은 뒤 <code>gzip</code>으로 압축을 진행한다.</li>
</ul>
<h4 id="4-2-tar-및-gzip-명령어-옵션-조합">4-2. tar 및 gzip 명령어 옵션 조합</h4>
<ul>
<li><strong>문법 :</strong> <code>tar &lt;옵션&gt; &lt;생성/해제할 파일명.tar.gz&gt; [대상 파일 또는 경로]...</code></li>
<li><strong>동시 처리 :</strong> 묶는 작업(<code>tar</code>)에 압축 엔진(<code>-z</code>)을 결합하여 묶음과 압축을 한 번의 명령어로 동시에 처리한다.</li>
</ul>
<table>
<thead>
<tr>
<th align="left">옵션</th>
<th align="left">실무 활용 상세 설명</th>
</tr>
</thead>
<tbody><tr>
<td align="left"><strong><code>-c</code> / <code>-x</code></strong></td>
<td align="left"><code>-c</code>는 새로운 묶음 파일을 생성(Create)하고, <code>-x</code>는 기존 묶음을 해제(Extract)함</td>
</tr>
<tr>
<td align="left"><strong><code>-z</code></strong></td>
<td align="left">묶음 작업에 그치지 않고 gzip 엔진을 활성화하여 용량을 압축하거나 해제함</td>
</tr>
<tr>
<td align="left"><strong><code>-v</code></strong></td>
<td align="left">묶이거나 풀리는 대상 파일들의 목록을 터미널 화면에 실시간으로 상세히 출력함</td>
</tr>
<tr>
<td align="left"><strong><code>-f</code></strong></td>
<td align="left">제어할 대상 파일명을 지정하며, <strong>무조건 옵션 문자열의 맨 끝자리에 위치해야만 에러가 나지 않음</strong></td>
</tr>
</tbody></table>
<h4 id="4-3-컨텍스트-변경-옵션--c의-진가">4-3. 컨텍스트 변경 옵션 -C의 진가</h4>
<ul>
<li><strong>목적지 강제 지정 :</strong> 압축 해제 시 뒤에 <code>-C /tmp</code> 처럼 경로를 주면 현재 위치를 벗어나지 않고 해당 폴더 내부에 깔끔하게 푼다.</li>
<li><strong>절대 경로 함정 탈출 :</strong> 압축 생성 시 <code>-C</code>로 상위 폴더에 먼저 진입한 뒤 묶어주면, 내부에 불필요한 상위 경로가 통째로 복사되는 것을 막아준다.</li>
</ul>

<h3 id="🔥-오늘의-딥다이브-회고">🔥 오늘의 딥다이브 (회고)</h3>
<h4 id="압축-파일-배포-시-상대-경로-지정과-컨텍스트-제어가-왜-중요한가">압축 파일 배포 시 상대 경로 지정과 컨텍스트 제어가 왜 중요한가?</h4>
<ul>
<li>실무에서 서버 간 코드를 이전할 때 <code>tar</code> 명령어에 전체 절대 경로를 주어 압축하면 백업 패키지 내부에 최상위 루트부터 시작하는 폴더 트리가 통째로 압축된다.</li>
<li>이 파일을 다른 운영 서버에서 해제하면 예기치 못한 위치에 디렉터리가 강제 빌드되거나 기존 시스템 파일을 덮어쓰는 일이 발생 할 수 있다.</li>
</ul>
