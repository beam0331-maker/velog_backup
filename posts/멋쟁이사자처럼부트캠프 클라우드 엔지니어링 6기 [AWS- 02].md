<h1 id="til-aws-ec2-생성-및-스토리지-탄력적-ipeip-설정-실습">[TIL] AWS EC2 생성 및 스토리지, 탄력적 IP(EIP) 설정 실습</h1>
<h2 id="1-aws-ec2-인스턴스-생성">1. AWS EC2 인스턴스 생성</h2>
<ul>
<li><p><strong>EC2(Elastic Compute Cloud)의 정의 및 개념</strong></p>
<ul>
<li>AWS에서 제공하는 클라우드 가상 컴퓨터 임대 서비스입니다. 물리적인 서버를 직접 구매할 필요 없이, 가상 공간에서 필요한 만큼의 컴퓨터 성능(CPU, 메모리, 용량 등)을 빌려 자유롭게 생성가능.</li>
</ul>
</li>
<li><p><strong>AMI(Amazon Machine Image) 및 인스턴스 유형 선택 기준</strong>
<img alt="" src="https://velog.velcdn.com/images/beam0331/post/41485b34-485a-4e83-9443-b61ac1adb472/image.png" /></p>
<ul>
<li>AMI는 서버 구동에 필요한 OS 및 소프트웨어 구성을 담은 템플릿이다. 프리티어 사용이 가능한 Ubuntu Server를 주로 선택한다.
<img alt="" src="https://velog.velcdn.com/images/beam0331/post/8189e2be-8af7-45db-b3ca-75d68e0bca2f/image.png" /></li>
<li>인스턴스 유형은 CPU 및 메모리 스펙을 결정하며, 실습 목적으로는 <code>t3.micro</code>를 선택한다.</li>
</ul>
</li>
<li><p><strong>키 페어(Key Pair) 생성 및 보안 관리</strong>
<img alt="" src="https://velog.velcdn.com/images/beam0331/post/226cfc41-204e-495c-86da-c9bb0fb89b75/image.png" /></p>
<ul>
<li>인스턴스에 안전하게 원격 접속하기 위한 비밀키 파일(.pem)을 생성한다. 비대칭 암호화 방식을 사용하며, 유실 시 서버 접속이 불가능하므로 로컬에 안전하게 보관해야 한다.</li>
</ul>
</li>
</ul>
<h2 id="2-네트워크-및-보안-그룹-설정">2. 네트워크 및 보안 그룹 설정</h2>
<h3 id="네트워크-설정-단계">네트워크 설정 단계</h3>
<p><img alt="" src="https://velog.velcdn.com/images/beam0331/post/e0534d5f-13ae-4575-b254-70092e7fd243/image.png" /></p>
<ul>
<li><strong>VPC(Virtual Private Cloud) 선택</strong><ul>
<li>ID: <code>vpc-07e95a7c53ba3e3df</code> (CIDR: <code>172.31.0.0/16</code>)</li>
<li>현재는 별도의 사설 네트워크를 구축하지 않고 AWS에서 기본으로 제공하는 <strong>기본값(Default VPC)</strong>을 사용한다.</li>
</ul>
</li>
<li><strong>서브넷 및 가용 영역(Subnet &amp; Availability Zone) 지정</strong><ul>
<li>서브넷과 가용영역을 사용자가 정의할 수 있다.</li>
<li>현재는 두 항목 모두 <strong>기본 설정 없음</strong>으로, 이 경우 AWS가 해당 리전 내의 가용 서브넷 중 하나를 임의로 선택하여 인스턴스를 배치한다.</li>
</ul>
</li>
<li><strong>퍼블릭 IP 자동 할당(Auto-assign public IP)</strong><ul>
<li><strong>활성화</strong> 상태를 유지한다. 인스턴스 부팅 시 외부 인터넷에서 접근 가능한 동적 퍼블릭 IP가 자동으로 부여된다.</li>
</ul>
</li>
<li><strong>방화벽(보안 그룹) 구성</strong><ul>
<li><strong>보안 그룹 생성</strong> 옵션을 선택한다. 기존 보안 그룹을 재사용하지 않고 본 인스턴스 전용 가상 방화벽 규칙을 새로 정의한다.</li>
</ul>
</li>
</ul>
<p><img alt="" src="https://velog.velcdn.com/images/beam0331/post/c60289c3-7b9c-4bc4-8bf6-7709ccff5421/image.png" /></p>
<ul>
<li><strong>SSH(22번 포트) 및 웹 트래픽(80, 443번 포트) 허용 규칙</strong><ul>
<li>원격 제어를 위해 SSH(22번 포트) 규칙을 추가하고 소스는 내 IP로 제한하는 것이 안전하다. 이후 웹 서비스 배포를 고려하여 HTTP(80) 및 HTTPS(443) 트래픽도 소스 무관(<code>0.0.0.0/0</code>)으로 허용하도록 설정한다.</li>
</ul>
</li>
</ul>
<h2 id="3-스토리지ebs-할당-및-볼륨-설정">3. 스토리지(EBS) 할당 및 볼륨 설정</h2>
<p><img alt="" src="https://velog.velcdn.com/images/beam0331/post/516f1c8a-f7a5-4615-8a80-e7b23ac06e42/image.png" /></p>
<ul>
<li><strong>EBS(Elastic Block Store)의 정의 및 블록 스토리지 특징</strong><ul>
<li>EC2 인스턴스에 사용할 수 있는 영구 블록 스토리지 볼륨이다. EC2와 독립적인 수명을 가지며 가용영역(AZ)레벨에 존재한다. 동적으로 용량을 확장할 수 한다.</li>
</ul>
</li>
<li><strong>볼륨 유형 및 크기 설정</strong><ul>
<li>스토리지의 유형과 크기, 처리량 등 을 설정할 수 있다..</li>
</ul>
</li>
<li><strong>스냅샷(Snapshot) 기반 백업 및 복제</strong><ul>
<li>특정 시점의 블록 상태를 그대로 캡처하여 백업, 복제 할 수 있다. 이 스냅샷을 활용하면 다른 가용 영역이나 다른 리전에 동일한 데이터 스토리지 볼륨을 복제하여 가용성을 높일 수 있다.</li>
</ul>
</li>
<li><strong>인스턴스 종료 시 볼륨 삭제 옵션 및 데이터 영속성</strong><ul>
<li>기본적으로 '종료 시 삭제' 옵션이 활성화되어 있어 EC2 인스턴스를 삭제하면 EBS 볼륨도 함께 삭제된다. 데이터 보존이 필요한 경우 이 옵션을 해제해야 한다.</li>
</ul>
</li>
</ul>
<h2 id="4-탄력적-ipelastic-ip-주소-할당-및-연결">4. 탄력적 IP(Elastic IP) 주소 할당 및 연결</h2>
<p><img alt="" src="https://velog.velcdn.com/images/beam0331/post/d1df313a-779d-4f97-a47f-e45ea98abeac/image.png" /></p>
<p><img alt="" src="https://velog.velcdn.com/images/beam0331/post/9a83aa67-b7e3-4f39-a455-c7b423ddcb82/image.png" /></p>
<ul>
<li><strong>동적 IP와 고정 IP(탄력적 IP)의 차이점</strong><ul>
<li>일반적인 EC2 인스턴스는 중지 후 재시작하면 퍼블릭 IP가 변경되는 동적 IP 주소를 가진다. 탄력적 IP는 인스턴스의 상태와 무관하게 고정되는 정적 퍼블릭 IP 주소이다.</li>
</ul>
</li>
<li><strong>탄력적 IP를 사용하는 이유와 인스턴스 재시작 시의 동작</strong><ul>
<li>도메인을 연결하거나 외부 가상 환경과의 통신 시 고정된 주소가 필요하기 때문에 할당한다. 인스턴스를 재시작하더라도 주소가 변경되지 않는다.</li>
</ul>
</li>
<li><strong>탄력적 IP 할당 및 EC2 인스턴스 연결 과정</strong><ul>
<li>AWS VPC 대시보드에서 탄력적 IP를 먼저 할당받은 후, 해당 IP 주소를 생성해 둔 EC2 인스턴스의 네트워크 인터페이스에 매핑(연결)한다.</li>
</ul>
</li>
<li><strong>탄력적 IP 사용 시 주의사항 및 비용 청구 기준</strong><ul>
<li>탄력적 IP는 할당받은 후 실행 중인 인스턴스에 연결해 두면 비용이 발생하지 않는다. 단, 인스턴스가 중지되어 있거나 연결하지 않고 IP만 보유하고 있는 경우 패널티 성격의 비용이 청구되므로 사용하지 않을 때는 반드시 릴리스(해제)해야 한다.</li>
</ul>
</li>
</ul>
