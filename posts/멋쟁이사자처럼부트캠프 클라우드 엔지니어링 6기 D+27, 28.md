<h2 id="1-자바-개발-플랫폼과-환경-구축">1. 자바 개발 플랫폼과 환경 구축</h2>
<ul>
<li><strong>Java SE (Standard Edition):</strong> 기본 JDK 및 JVM 기반 개발 도구</li>
<li><strong>Java EE (Enterprise Edition / Jakarta EE):</strong> 웹 애플리케이션 개발 플랫폼으로, Servlet/JSP 스펙을 정의.</li>
<li><strong>Tomcat 10:</strong> Apache에서 제공하는 웹 컨테이너(서버)<ul>
<li><strong>패키지 변경:</strong> Tomcat 10부터는 패키지 이름이 <code>javax.*</code>에서 <code>jakarta.*</code>로 변경되었다. (JDK 17 이상 권장)</li>
<li><strong>배포 구조:</strong> 프로젝트를 <code>WAR</code> 파일로 압축하여 <code>webapps</code> 폴더에 넣으면 톰캣이 자동으로 압축을 해제하며 서비스가 시작된다.</li>
</ul>
</li>
</ul>
<h2 id="2-jspjavaserver-pages의-3단계-동작-방식">2. JSP(JavaServer Pages)의 3단계 동작 방식</h2>
<p>JSP는 HTML같이 브라우저가 바로 렌더링하는 것이 아니라, 서버 내부에서 변환 과정을 거친다.</p>
<ol>
<li><strong>변환(Translation):</strong> <code>.jsp</code> 파일이 <code>.java</code> 서블릿 소스 코드로 변환된다.</li>
<li><strong>컴파일(Compilation):</strong> 생성된 <code>.java</code> 파일이 실행 가능한 <code>.class</code> 파일로 컴파일된다.</li>
<li><strong>실행(Execution):</strong> 메모리에 적재된 클래스가 요청을 처리하고 결과를 HTML로 브라우저에 응답한다.</li>
</ol>
<h2 id="3-서블릿servlet의-핵심과-계층-구조">3. 서블릿(Servlet)의 핵심과 계층 구조</h2>
<p>서블릿은 계층적인 인터페이스 구현과 클래스 상속 구조를 통해 기능을 분담한다.</p>
<h3 id="가-상속-및-구현-관계-inheritance--implementation">가. 상속 및 구현 관계 (Inheritance &amp; Implementation)</h3>
<ol>
<li><strong><code>Servlet</code> (Interface):</strong> 모든 서블릿의 핵심 생명주기 메서드를 정의한다.</li>
<li><strong><code>ServletConfig</code> (Interface):</strong> 서블릿 초기화 설정 정보를 전달한다.</li>
<li><strong><code>GenericServlet</code> (Abstract Class) [ <code>implements Servlet, ServletConfig</code> ]:</strong> 프로토콜에 관계없이 공통적으로 필요한 기능을 구현한다.</li>
<li><strong><code>HttpServlet</code> (Abstract Class) [ <code>extends GenericServlet</code> ]:</strong> HTTP 프로토콜에 특화된 기능(doGet, doPost 분기 등)을 제공한다.</li>
<li><strong><code>사용자 정의 서블릿</code> (Concrete Class) [ <code>extends HttpServlet</code> ]:</strong> 개발자가 실제 비즈니스 로직을 구현.</li>
</ol>
<h3 id="나-서블릿-매핑-예시-코드">나. 서블릿 매핑 예시 코드</h3>
<ul>

</li>
</ul>
<h2 id="4-서블릿-생명주기lifecycle와-동시성-제어">4. 서블릿 생명주기(LifeCycle)와 동시성 제어</h2>
<ul>
<li><strong>LifeCycle:</strong> <code>init()</code> (최초 1회 생성) → <code>service()</code> (요청 시마다 호출) → <code>destroy()</code> (서버 종료 시 소멸).</li>
<li><strong>Thread-safe 설계:</strong> 서블릿은 단 하나만 생성되어 공유되는 <strong>싱글톤(Singleton)</strong> 방식이다. 데이터 무결성을 위해 여러 사용자가 접근할 수 있는 <strong>인스턴스 변수</strong>대신, 반드시 <strong>로컬 변수</strong>를 사용해야한다.</li>
</ul>
<h2 id="5-요청request-데이터-처리-상세">5. 요청(Request) 데이터 처리 상세</h2>
<p>브라우저에서 전달된 파라미터를 추출하는 핵심 방법들이다.</p>
<pre><code class="language-java">// 1. 단일 값 추출
String username = request.getParameter(&quot;username&quot;); 

// 2. 다중 선택값 추출 (체크박스 등)
String[] hobbies = request.getParameterValues(&quot;hobby&quot;); 

// 3. 전체 파라미터 이름 순회 처리
Enumeration&lt;String&gt; enu = request.getParameterNames();
while(enu.hasMoreElements()) {
    String key = enu.nextElement();
    String value = request.getParameter(key);
}</code></pre>
<h2 id="6-상태-유지를-위한-3가지-scope">6. 상태 유지를 위한 3가지 Scope</h2>
<p>HTTP는 Connectionless이므로 응답하는 순간 지속적인 연결이 헤제된다. 이를 보완하기 위해 컨테이너는 데이터 저장소를 제공한다. 모든 객체는 <code>setAttribute()</code>, <code>getAttribute()</code> 메서드를 공통으로 사용한다.</p>

<h3 id="나-scope-데이터-활용-예시-코드">나. Scope 데이터 활용 예시 코드</h3>
<pre><code class="language-java">@WebServlet(&quot;/ScopeTest&quot;)
public class ScopeTestServlet extends HttpServlet {
    protected void doGet(HttpServletRequest request, HttpServletResponse response) throws ServletException, IOException {
        // 1. 데이터 저장
        request.setAttribute(&quot;req&quot;, &quot;Request Data&quot;); // 현재 요청 내에서만
        HttpSession session = request.getsession()
        session.setAttribute(&quot;sess&quot;, &quot;Session Data&quot;); // 세션 유지 동안

        ServletContext ctx = getServletContext()
        ctx.setAttribute(&quot;app&quot;, &quot;Application Data&quot;); // 서버 종료 전까지

        // 2. 데이터 조회
        String reqVal = (String) request.getAttribute(&quot;req&quot;);
        String sessVal = (String) session.getAttribute(&quot;sess&quot;);
        String appVal = (String) ctx.getAttribute(&quot;app&quot;);
    }
}</code></pre>
<h2 id="7-filter-및-db-연동-mybatis">7. Filter 및 DB 연동 (MyBatis)</h2>
<h3 id="가-필터filter-구현-예시-코드">가. 필터(Filter) 구현 예시 코드</h3>
<p>서블릿 실행 전(요청 가로채기)과 후(응답 전 작업)의 공통 작업을 처리한다.</p>
<pre><code class="language-java">@WebFilter(&quot;/*&quot;) // 모든 요청에 필터 적용
public class MyFilter implements Filter {
    @Override
    public void doFilter(ServletRequest request, ServletResponse response, FilterChain chain) 
            throws IOException, ServletException {

        // [전처리] 서블릿 호출 전 실행
        request.setCharacterEncoding(&quot;utf-8&quot;); 
        System.out.println(&quot;필터 전처리: 인딩 설정 완료&quot;);

        // 다음 필터나 서블릿으로 제어권 전달
        chain.doFilter(request, response);

        // [후처리] 서블릿 호출 후 실행
        System.out.println(&quot;필터 후처리: 응답 전 작업 수행&quot;);
    }
}</code></pre>
<h3 id="나-mybatis-연동-기초">나. MyBatis 연동 기초</h3>
<ul>
<li>웹 프로젝트에서는 라이브러리(<code>.jar</code>) 파일을 <code>WEB-INF/lib</code> 폴더에 배치해야 클래스패스가 자동으로 잡힌다.</li>
<li>XML 설정을 통해 SQL과 자바 코드를 분리하며, <strong>Controller(Servlet) - Service - DAO - MyBatis</strong>로 이어지는 계층형 아키텍처를 구성하여 연동한다.</li>
</ul>
