<h4 id="1-1-인프라-구축-방식의-분류">1-1. 인프라 구축 방식의 분류</h4>

<h4 id="1-3-vmware-네트워크-구조">1-3. VMWare 네트워크 구조</h4>
<ul>
<li><strong>NAT vs Host-only :</strong> NAT는 가상 머신이 외부 인터넷으로 나갈 수 있게 돕는 통로이며, Host-only는 외부망을 차단하고 PC-가상 머신 간 내부 통신만 허용한다.</li>
<li><strong>게이트웨이 규칙 :</strong> VMWare NAT 환경의 가상 라우터 주소 끝자리는 무조건 <strong><code>.2</code></strong>로 고정된다. 이를 <code>.1</code>로 설정하면 외부 통신이 단절되므로 주의해야 한다.</li>
<li><strong>게이트웨이로 <code>.1</code>을 사용하면 안 되는 이유 :</strong> 끝자리 <code>.1</code>은 외부 인터넷으로 나가는 문이 아니라 호스트 PC(윈도우) 자체의 가상 랜카드 주소이기 때문이다.</li>
</ul>
<h4 id="1-4-cidr-표기법과-넷마스크-레벨-서브네팅">1-4. CIDR 표기법과 넷마스크 레벨 서브네팅</h4>

</ul>

<h3 id="2-리눅스의-심장과-시스템-구조">2. 리눅스의 심장과 시스템 구조</h3>
<h4 id="2-1-gnu-프로젝트와-오픈소스-생태계">2-1. GNU 프로젝트와 오픈소스 생태계</h4>
<ul>
<li><strong>GNU 프로젝트 :</strong> 소프트웨어 소스코드의 투명한 공개를 주장하는 리처드 스톨만의 자유 소프트웨어 운동으로, 리눅스의 뼈대가 되었다.</li>
<li><strong>리눅스 배포판 :</strong> 커널에 쉘과 응용프로그램을 결합한 형태로, 실무에서는 데비안 계열(Ubuntu, <code>apt</code>)과 레드햇 계열(CentOS, <code>dnf/yum</code>)이 주로 쓰인다.</li>
</ul>
<h4 id="2-2-리눅스-운영체제-3계층-아키텍처">2-2. 리눅스 운영체제 3계층 아키텍처</h4>
<blockquote>
<p> <strong>리눅스 아키텍처 계층 구조</strong>
하드웨어(H/W) ➡️ 커널(Kernel) ➡️ 쉘(Shell) ➡️ 응용프로그램(Application)</p>
</blockquote>
<ul>
<li><strong>커널 (Kernel) :</strong> 프로세스, 메모리, 하드웨어 자원을 직접 통제하고 소프트웨어와 조율하는 시스템의 핵심</li>
<li><strong>쉘 (Shell) :</strong> 사용자가 입력한 명령어를 해석 및 검증하여 커널에게 전달하는 인터페이스이다.</li>
</ul>
<h4 id="2-3-ssh-비대칭키-기반-원격-보안-접속-프로세스">2-3. SSH 비대칭키 기반 원격 보안 접속 프로세스</h4>
<ul>
<li><strong>키 페어 생성 :</strong> <code>ssh-keygen</code> 명령어를 사용하여 한 쌍으로 연동되는 공개키(Public Key)와 개인키(Private Key)를 생성한다.</li>
<li><strong>키 검증 및 배치 :</strong> 서버의 <code>~/.ssh/authorized_keys</code>에 공개키를 등록하고, 클라이언트(PC)는 개인키(.pem)를 보관하여 접속 시 검증한다.</li>
<li><strong>소유 권한 제한 :</strong> 보안을 위해 <code>chmod 600</code> 명령으로 키 파일 권한을 소유자 전용으로 엄격히 제한해야만 정상적인 원격 접속이 가능하다.</li>
</ul>
<hr />
<h3 id="3-리눅스-파일-시스템과-권한환경-관리">3. 리눅스 파일 시스템과 권한/환경 관리</h3>
<h4 id="3-1-파일-시스템-트리-계층-구조와-특성">3-1. 파일 시스템 트리 계층 구조와 특성</h4>
<ul>
<li><strong>단일 트리 파일 시스템 :</strong> 드라이브 구분 없이 최상위 루트(<code>/</code>)에서 시작하며, 디렉터리와 하드웨어 장치 등 모든 개체를 파일로 취급한다.</li>
<li><strong><code>/bin</code> :</strong> 사용자 및 관리자가 공통으로 빈번하게 사용하는 기본 실행 명령어가 모여있는 폴더이다.</li>
<li><strong><code>/etc</code> :</strong> 패키지 설정, 네트워크, 계정 등 시스템 설정 파일 저장소이다.</li>
<li><strong><code>/var</code> &amp; <code>/tmp</code> :</strong> <code>/var</code>는 에러 로그 등 가변 데이터가 누적되는 곳이며, <code>/tmp</code>는 시스템 재부팅 시 삭제되는 임시 파일 버퍼 공간이다.</li>
</ul>
<h4 id="3-2-프롬프트-권한-통제-메커니즘">3-2. 프롬프트 권한 통제 메커니즘</h4>
<ul>
<li><strong>일반 사용자 (<code>$</code>) :</strong> 시스템의 최소 권한 상태, 할당받은 본인만의 안전 구역인 홈 디렉터리(<code>~</code>) 내부에서만 제어가 허용된다.</li>
<li><strong>최고 관리자 (<code>#</code>) :</strong> 리눅스 시스템의 전권을 가진 <code>root</code> 계정으로, 패키지 설치 및 서비스 통제 등 운영체제 전체를 제어한다.</li>
<li><strong><code>sudo -s</code> (권한 유지) :</strong> 현재 사용자의 쉘 환경 변수(작업 디렉터리 등)를 그대로 유지한 채 <code>root</code> 권한만 임시로 획득한다.</li>
<li><strong><code>sudo su</code> (계정 전환) :</strong> <code>root</code> 계정으로 전환은 되지만, 기존 사용자의 환경 변수가 일부 섞여 남아있어 예기치 않은 오류가 발생할 수 있다.</li>
<li><strong><code>sudo su -</code> (완전 전환) :</strong> 기호 <code>-</code>는 '로그인 쉘'을 뜻하며, 관리자 전용 환경 변수와 홈(<code>/root</code>)으로 완벽히 초기화하여 접속하며 가장 권장하는 방식이다.</li>
</ul>

<h4 id="4-3-ls--l-명령어-상세-출력-구조-분석">4-3. <code>ls -l</code> 명령어 상세 출력 구조 분석</h4>
<ul>
<li><strong>출력 예시 :</strong> <code>-rw-r--r-- 1 root root 4096 May 27 15:30 text.txt</code></li>
<li><strong>파일 유형 및 권한 (<code>-rw-r--r--</code>) :</strong> 첫 글자는 파일 종류(<code>-</code>: 일반, <code>d</code>: 디렉터리, <code>l</code>: 심볼릭 링크, <code>b</code>/<code>c</code>: 장치 파일)를 나타낸다. 이후 9자리는 소유자/그룹/기타 사용자의 읽기/쓰기/실행(<code>rwx</code>) 권한이다.</li>
<li><strong>소유자 및 그룹 (<code>root root</code>) :</strong> 파일 생성자(소유 계정)와 그 계정이 속한 그룹명을 의미하며, 파일 접근 권한 통제의 기준이 된다.</li>
<li><strong>용량 및 시간 (<code>4096 May...</code>) :</strong> 파일의 실제 크기와 가장 마지막으로 내용이 수정된 타임스탬프를 나타낸다.</li>
</ul>

<h3 id="🔥-오늘의-딥다이브-회고">🔥 오늘의 딥다이브 (회고)</h3>
<h4 id="존재하지-않는-명령어를-쳤을-때-에러를-내뱉는-주체는-누구인가">존재하지 않는 명령어를 쳤을 때, 에러를 내뱉는 주체는 누구인가?</h4>
<ul>
<li>터미널 창에 <code>lss</code>처럼 비정상적인 명령어를 쳤을 때 에러를 발생시키는 주체는 '커널'이 아니라 명령어 해석기인 '쉘(Shell)'이다.</li>
<li>쉘은 입력된 명령어가 내부 캐시나 환경 변수 경로(<code>$PATH</code>)에 존재하는지 먼저 확인하는 유효성 검증 단계를 거친다.</li>
<li>파일이 없으면 쉘 선에서 즉시 에러를 발생시키며, 이 경우 커널을 호출하는 시스템 콜(System Call)은 아예 발생하지 않는다.</li>
<li>즉, 커널은 쉘의 필터링을 통과한 정상 명령어만 전달받아 하드웨어를 제어한다는 명확한 역할 분담 원리를 이해할 수 있었다.</li>
</ul>
